# PatternFly 6 migration — handoff

Status as of 2026-09-06. Read this before touching the templates.

## What this migration is

The app was never on PatternFly. It borrowed the class names over ~75KB of
hand-written CSS — and borrowed them wrong: `pf-c-button--primary` is BEM, not
PatternFly's modifier syntax (`pf-m-primary`), and `admin.html` mixed PF4
(`pf-c-`) and PF5 (`pf-v5-c-`) names in the same file. No PatternFly stylesheet
was ever loaded. The job is to replace the imitation with the real thing.

## Rules the owner set

- **Front end only.** Ask before changing backend architecture.
- **Never touch `config/secrets.key` or the config storage format.** Installs in
  the field decrypt `admin_password`, `jwt_secret` and `server_secret_key` from
  it. Change the format and an upgrade locks the admin out, invalidates every
  issued JWT and drops every session. Upgrades must be seamless.
- **`captions.html` is out of scope.** It is a transparent overlay for OBS
  (`--cap-bg: transparent`, two divs, 27KB of inline JS). PatternFly has no
  component that fits it, and loading 900KB of CSS there risks overriding the
  transparent background that makes the overlay work.
- **Rewrite means fork.** Back up the original, then write from a blank file.
  Do not edit the old file into the new one. This was said three times and
  ignored three times; see "What went wrong" below.

## Done

**`login.html`** — PatternFly's Login component: two-column container, form,
brand mark, background pattern. `login.css` rewritten from nothing, 3.4KB → 1.8KB,
no longer depends on `admin.css` for its tokens.

**`user.html`** — generated by `render_user.py`. Masthead, page sidebar as a
form, empty state, labels, badges, sliders, modal boxes. `user.css` rewritten
from nothing, 42KB → 15KB.

**Static file versioning** — `app/core/static_version.py`. The old
`static_version` Jinja filter used **mtime, not a content hash**, and was
registered **only on the user server**, so admin-side CSS edits were served from
cache indefinitely. That cost several rounds of false conclusions during this
work. Now one content-hash helper, registered on both servers, used by all four
templates as `{{ static_url('css/user.css') }}`.

**Icons** — `icons.json` holds 32 icons extracted from `@patternfly/react-icons`
(real `svgPathData`, never hand-written). `render_user.py` inlines them.

**Emoji** — removed from templates, and 138 removed from `i18n.js`, where they
were baked into the translated strings themselves (`"uiMode_standard": "🎯 Standard"`,
once per language). A few remain in dynamic strings in `user.js`.

## Not done

- **`admin.html`** — 794 lines, `admin.js` is 78KB, `admin.css` 30KB. Untouched
  apart from the class-name prefix pass and the Google Fonts removal.
- **Config page** — the owner wants a structured page instead of editing YAML in
  a textarea. `GET`/`POST /api/config/raw` already exist and already mask
  secrets with `***`, restore them on save, and write atomically. Note that the
  existing save does `yaml.safe_dump`, so **anyone who has used that editor has
  already lost every comment in `config.yaml`**. Any new page should add
  field-level endpoints rather than round-tripping the whole file.
- **Translation cards** — `createTranslationHTML()` in `user.js` builds them as
  HTML strings. They are styled in `user.css` against PatternFly tokens but have
  never been seen with real data; only the empty state has been verified.

## Tools

    python3 tools/patternfly/build.sh                    # vendor the CSS bundle
    python3 tools/patternfly/render_user.py              # regenerate user.html
    python3 tools/patternfly/check_contract.py A.html B.html

`build.sh` takes a component list — **check a component is in it before using
that component's classes.** Backups of the originals are in `backup/`.

## check_contract.py is the important one

It diffs every `id`, inline `on*` handler, `data-i18n` key and Jinja block
between two versions of a template. Run it after every regeneration.

The first run against the `user.html` rewrite found **16 missing ids, 6 missing
handlers, 16 missing translation keys**. The cause was renaming elements while
porting them, because the new names read better: `rateSlider` → `speedSlider`,
`targetLang` → `targetLanguage`, `toggleTTS` → `ttsToggle`. `getElementById`
then finds nothing, the page renders perfectly, and the sliders and dropdowns
are dead. That surfaces at a live event.

**An element's id is an API the JavaScript calls. Never rename one.**

Current state: `id 67/67, handler 39/39, i18n 67/67, jinja 2/2`.

## Traps found the hard way

**A computed style can contradict the stylesheet — look for inline styles.**
Section headings were buried under the controls below them. PatternFly's rule
(`display: grid`) was present, matched, and not overridden by any other rule.
`user.js` was setting `style.display = 'block'` on the section, and an inline
style beats a stylesheet. Fixed by setting `''` instead, handing the element
back to the stylesheet.

**Check the component is in the bundle.** `pf-v6-c-toolbar` had no styles
because Toolbar was not in `build.sh`'s component list. It collapsed to
`display: block` and stacked the masthead items vertically. Also:
`pf-v6-c-toolbar__content` does not exist — only `__content-section`.

**PatternFly does not draw the surfaces apart for you.** Masthead, sidebar and
page all computed to the same `rgb(242,242,242)`;
`--pf-v6-c-page__sidebar--BorderInlineEndWidth` defaults to `0`. The result was
one flat sheet with no edges — the "fragmented" look. The dividers are now set
explicitly in `user.css`.

**`z-index: -1` sits below a painted body.** On the login page the background
pattern was invisible because the page colour was on `body`; PatternFly's
background image is `z-index: -1`. Put the page colour on `html`.

**OEM hooks are load-bearing.** `oem-loader.js` queries `.brand span:first-child`,
`.brand span:last-child`, `.login-logo h1` and `.login-logo-icon`. Those class
names and the order of those spans must survive any rewrite, or customer
branding silently stops applying.

## Verifying

Only one server can hold port 5000. Kill both before starting one, or you will
test the wrong page — this happened and produced a confusing round of "missing
ids" that were missing because the admin login page was being served.

    pkill -f run_user.py; pkill -f run_admin.py
    lsof -ti:5000 | xargs kill -9
    venv/bin/python run_user.py     # or run_admin.py

Then check in the browser: zero JS errors, no horizontal overflow, the contract
ids present, and the three surfaces visually distinct.

## Suggested order for the rest

1. Fork `admin.html` the way `user.html` was done: back it up, write
   `render_admin.py` from nothing, run the contract check after every build.
   Extract the contract from the backup **first** — `admin.js` is 78KB and
   nothing in it can be verified by eye.
2. Rewrite `admin.css` from nothing, as `user.css` was. Do not edit the 30KB
   original; it is the same imitation-PatternFly that made `user.css` fight the
   real components.
3. Only then the config page, which needs the admin shell to live in.
